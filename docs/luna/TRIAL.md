# Trial / Staging Behavior

Trial experiences should demonstrate the same Luna capability model and design-system behavior as authenticated Builder experiences, subject to trial-specific restrictions.

## Core rules
- Generated trial pages use registered Sparks and centralized theme/design tokens.
- A trial site should maintain a coherent theme across its generated pages.
- Explicit rebrand requests may use the same validated premium color-family system.
- Heading, radius, spacing, media, and contrast rules should match the main Builder where the feature is available.
- Trial-specific restrictions must be explained accurately rather than bypassed.

## Conversation
Luna should answer capability questions in trial mode from the same canonical documentation. If an action requires sign-in/purchase/authentication, the reply and contextual action should say so clearly.

## Credits
Trial credit behavior follows CREDITS.md and configured trial allowances. Manual non-AI UI actions do not become billable merely because they occur in trial mode.
